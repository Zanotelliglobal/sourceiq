> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Scope Note (read first)

This phase is **not** a design/UX phase. It is a **text-string brand rename**
("SourceIQ" → "SourceGPT") applied to existing, unchanged UI surfaces. It is
only routed through the UI workflow because the repo's deterministic
UI-plan-gate flags `frontend: true` when page/component files are touched —
and this rename touches many of them, purely at the string level.

**No new components, layouts, visual styles, interaction patterns, or design
tokens are introduced or changed by this phase.** Every section below that
would normally define new design decisions is marked N/A with a reason,
per this agent's scope-creep guardrail. The one genuinely design-relevant
question this phase raises — whether the OG image / wordmark needs a new
visual asset — is answered concretely below (it does not).

## OG Image / Wordmark Asset Decision

**Decision (already made in CONTEXT.md "Claude's Discretion", confirmed correct by this research pass):** a plain text-based swap is sufficient — **no new logo/wordmark asset is required this phase.**

Confirmed by inspection:
- `app/opengraph-image.tsx` renders the brand name as a plain `<div>` text node (`fontSize: 32, fontWeight: 700`) inside the Next.js `ImageResponse` — not an embedded image/SVG. Swapping the string is sufficient; no new visual asset needed.
- `components/TopNav.tsx` and `app/supplier/rfi/page.tsx` render the "logo" as a small blue rounded-square icon (a generic abstract mark, not brand-name-derived) plus a plain text wordmark span — the icon itself contains no brand letters and needs no change.
- The two dead SVG assets in `docs/brand/` (`sourceiq-wordmark.svg`, `sourceiq-mark-square.svg`) are unreferenced by any live page, so they do not block this phase's "text-only, no new asset" approach. If a future phase wants a real designed logo, that's new-asset work explicitly deferred (per CONTEXT.md's Deferred Ideas).
- One specific risk if the scripted pass blindly touches `sourceiq-mark-square.svg`: its monogram is hardcoded as 2 characters ("IQ") at `font-size: 128` centered in a 300px square. A literal find/replace would produce "GPT" (3 characters) at the same font-size, which was not designed for 3 characters and may look visually off (tighter kerning, closer to edges) — this is flagged as an **unresolved planner assumption** in UI Considerations below, not silently auto-fixed, since the asset is unreferenced/dead and the correct fix (resize vs. re-abbreviate vs. leave/delete the dead asset) is a human call, not a mechanical one.
