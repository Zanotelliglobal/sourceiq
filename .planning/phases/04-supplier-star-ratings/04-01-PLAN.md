<objective>
**As a** buyer, **I want to** rate a supplier 1-5 stars and have that rating
attach to the supplier's durable repository identity, **so that** the rating
accumulates and is visible across every event where I encounter that supplier
within my org — instead of resetting per event. (User story reframed from
ROADMAP.md's Phase 4 Goal line per MVP_MODE; no content invented beyond
restating the already-approved goal in template form.)

This phase closes a gap Phase 3 deliberately left open: `org_supplier_data.rating`
already exists in the schema (`lib/db.ts:340`) but nothing writes to it, and the
per-event `suppliers` table has no column linking a row back to its repository
identity. `identityId`/`identityIdDeepen` are already computed inside
`lib/process-supplier.ts` during every discovery path but are discarded after the
repository upsert (D-01). This plan (1) adds `suppliers.identity_id` and wires it
in all three `makeProcessSupplier*()` factories, and (2) builds the rating
feature itself (write path, read path, UI) on top of that link — implementing
RATE-01, RATE-02, RATE-03 per `.planning/REQUIREMENTS.md`.

**Assumption-delta architecture-checkpoint determination (recorded per
orchestrator contribution, not skipped silently):** `suppliers.identity_id` is a
foreign-key back-link into an already-designed two-table repository
architecture (Phase 3's `supplier_identities`/`org_supplier_data` split). It is
not a second identity model and does not promote a singular field to plural —
`identityId`/`identityIdDeepen` are already-computed values from Phase 3; this
phase only persists an existing value onto a column that did not yet exist.
Determination: **no-change** — the promote/add-alongside/no-change decision
does not meaningfully fire here.

**API Coverage Decision:** recorded at `.planning/phases/04-supplier-star-ratings/COVERAGE.md`
— no external API/service is introduced this phase (internal DB column + internal
route action + UI only).

Purpose: Give buyers a durable, cross-event quality signal on suppliers that
persists at the org level, without disturbing the existing per-event
`feedback_signal` control.
Output: `suppliers.identity_id` column; `updateOrgSupplierDataRating()`;
`set_rating` API action; JOIN-enabled GET read path; wired `DetailPanel` star
control; extended automated test coverage across both affected test files.
</objective>
